# Mimari Kararlar / Architecture Decisions

Ayrıntılı ADR'ler `docs/adr/` altındadır. Bu dosya özet dizindir.

| ADR | Karar | Gerekçe özeti |
|-----|-------|----------------|
| 0001 | Tek Poetry paketi (`src/visionroute/`) içinde modüler monolit; `apps/packages` çoklu-paket düzeni yerine import-linter ile sınır zorlaması | Tek ekip, tek dağıtım hattı; paketleme yükünü azaltır, sınırlar statik analizle korunur |
| 0002 | Worker sistemi: Celery/Dramatiq yerine PostgreSQL outbox + `FOR UPDATE SKIP LOCKED` tüketici | Daha az hareketli parça; outbox zaten zorunlu; Redis broker tek hata noktası olmaktan çıkar; Redis önbellek/hız sınırlama için kalır |
| 0003 | JWT imzalama: RS256 (asimetrik), kısa ömürlü access token + veritabanında hash'lenmiş refresh token, sunucu tarafı iptal | Simetrik anahtar sızıntı riskini azaltır; iptal edilebilirlik zorunlu |
| 0004 | Parola: Argon2id (argon2-cffi) | Modern bellek-sert KDF |
| 0005 | Kimlik ID'leri: UUIDv7 (uuid_extension yok; uygulama tarafında üretim, `uuid6` kütüphanesi yerine stdlib tabanlı üretici) | Sıralanabilir, indeks dostu |
| 0006 | Konum verisi: çekirdek kolonlar `latitude/longitude double precision` + PostGIS `geography` kolonu ve GIST indeksi migration'da `CREATE EXTENSION postgis` ile | PostGIS prod'da zorunlu; çekirdek sorgular PostGIS'siz de çalışır |
| 0007 | Frontend: Next.js (App Router) + TypeScript strict + Tailwind + TanStack Query + Zod + MapLibre GL | Spesifikasyon gereksinimi; MapLibre lisans açısından güvenli |
| 0008 | LLM kullanımı varsayılan **kapalı**; yalnızca şema doğrulamalı, kanıt-temelli, sınırlandırılmış görevler | Spesifikasyon 5.3 |
| 0009 | Faturalama: sağlayıcı soyutlaması + manuel fatura modu varsayılan; Stripe adaptörü yalnızca yapılandırıldığında | Türk kurumsal satış gerçeği; kart verisi saklanmaz |
| 0010 | Kiracı izolasyonu: uygulama katmanı + PostgreSQL RLS (oturum değişkeni `app.tenant_id`) çift katman | Derinlemesine savunma |

## 2026-09 tamamlama geçişi kararları

| Karar | Gerekçe |
|-------|---------|
| import-linter katmanları: `cli` en üstte, `api \| worker \| scheduler` altında | CLI süreçlerin kompozisyon köküdür (worker ve scheduler'ı başlatır). Önceki sözleşme `cli`'yi bu modüllerle kardeş katmana koyduğu için temel hatta zaten KIRIKTI; kural gevşetilmedi, gerçek bağımlılık yönü tanımlandı |
| Her kimlik doğrulamalı istekte üyelik/rol veritabanından yeniden doğrulanır | Access token 15 dk yaşar; üyelikten çıkarılan, rolü düşürülen veya devre dışı bırakılan kullanıcı eski yetkisini token süresi dolana kadar koruyordu. İstek başına tek indeksli sorgu maliyeti kabul edildi |
| Worker her outbox olayını kendi SAVEPOINT'inde işler; webhook teslimatı ayrı işlemde | Tek bir veritabanı hatası tüm partiyi geri alıyor ve `attempts` hiç artmadığı için dead-letter'a ulaşılamıyordu (sonsuz zehirli döngü). Ağ çağrıları outbox kilitlerini tutmamalı |
| Scheduler turu `pg_try_advisory_xact_lock` ile tekilleştirilir | Rolling deploy veya yanlışlıkla çoklu replika çift çalıştırma üretmemeli |
| Güvenlik olayı tekilleştirme: sabit 30 sn saat kovası yerine ±30 sn kayan pencere + araç/tip bazlı advisory lock | Sabit kova 5 sn arayla gelen iki sert freni kova sınırında iki olaya bölüyordu (test ~1/6 oranında kırmızıydı) |
| Kanıt yükü `events.evidence.read` izni ister | `events.read` (ör. analist) kanıtı görmemeli; izin kataloğu bunu zaten ayırıyordu ancak uç nokta zorlamıyordu |
| CSV raporlarında kiracı kontrollü metin formül enjeksiyonuna karşı `'` ile öneklenir | OWASP CSV injection |
| İstek gövdesi boyut sınırı (varsayılan 12 MiB) ASGI katmanında | Uvicorn varsayılan olarak sınır uygulamaz; chunked gövdeler dahil |
| `X-Request-ID` yalnızca `[A-Za-z0-9._:-]{1,64}` ise kabul edilir | İstemci değeri loglara ve yanıta yansıtılıyordu (log enjeksiyonu) |
| Alan şifreleme: `cryptography` Fernet + sürümlü anahtar halkası (`enc1:<kid>:<token>`), anahtarlar yapılandırmadan (Secrets Manager) | Yeni bağımlılık yok; doğrulanmış, kimlik doğrulamalı şifreleme; kesintisiz rotasyon (`visionroute security reencrypt`). KMS envelope çağrısı her şifre çözmede ağ gecikmesi ve maliyet getirirdi; anahtar zaten KMS şifreli Secrets Manager'da tutuluyor |
| Webhook sırrı şifreleme geçişi üç revizyonda: şema ekle → veri doldur → düz metni kaldır | AGENTS.md kural 9 (veri doldurma şemadan ayrı). Veri adımı `app.rls_bypass` açar: FORCE RLS nedeniyle aksi halde 0 satır görüp düz metin sütununu şifrelemeden silecekti. Anahtar yoksa ve satır varsa migration durur |
| Hız sınırlama: Redis sabit pencere (üretim), bellek içi (yalnızca yerel/test); Redis kesintisinde fail-open + log | CLAUDE.md: Redis yalnızca önbellek/hız sınırlama. Kimlik doğrulamanın önbellek kesintisiyle çökmesi kabul edilmez; hesap kilitleme ayrıca korur. Anahtarlar SHA-256 ile hash'lenir (Redis'te e-posta/IP yok) |
| Giriş sınırı iki katmanlı: (IP, e-posta) başına 10/dk + IP başına 100/dk | Tek NAT arkasındaki ofis kullanıcılarını engellemeden kaba kuvveti yavaşlatır |
| E-posta: `email_messages` işlemsel outbox'ı + worker teslimatı (claim → işlem dışı gönderim → sonuç), stdlib `smtplib` (yeni bağımlılık yok); arka uçlar `smtp` / `file` (yerel .eml) / `memory` (test) | İş işlemi SMTP'ye bağımlı olmamalı; geri alınan işlem e-posta göndermemeli. En az bir kez teslim + kira süresi; yeniden denemeler aynı Message-ID'yi taşır. 5xx kalıcı, 4xx/ağ/kimlik doğrulama geçici |
| Tek kullanımlık bağlantı token'ları API yanıtında **hiç** dönmez; e-postada URL fragmanında (`#token=`) taşınır; outbox'ta şifreli tutulur, gönderimden sonra silinir | Fragment tarayıcıdan sunucuya gönderilmez → web/proxy erişim loglarına düşmez. Geliştirme için ayrı "token açığa çıkarma" modu gerekmedi: yerelde `file` arka ucu, testlerde `memory` arka ucu |
| MFA: `pyotp` (RFC 6238, yeni bağımlılık), sır alan şifreli, son kabul edilen zaman adımı saklanır (replay), giriş challenge'ı 5 dk / 5 deneme, 10 adet 80-bit kurtarma kodu (SHA-256) | Kanıtlanmış kütüphane; kendi TOTP gerçeklememizi yazmadık. Parola doğrulaması + kod olmadan kapatılamaz |
| Organizasyon MFA politikası (`organization_settings.security.mfa_required`): etkinleştiren kişinin kendisinde MFA açık olmalı; kaydı olmayan üyeler yalnızca `/api/v1/auth/*` uçlarına erişir | Kilitlenmeden zorunlu kayıt akışı |
| Yönetici MFA sıfırlaması yalnızca **sahip** rolüne açık ve kullanıcı başka organizasyona üyeyse reddedilir (RLS-bypass sorgusu ile) | MFA hesap düzeyindedir; bir kiracının sahibi başka kiracıdaki güvenliği zayıflatamaz. RLS altında diğer üyelikler görünmeyeceği için kontrol bilinçli olarak bypass oturumunda yapılır |
| Parola/MFA sıfırlamasında `users.sessions_revoked_at` damgası; bundan önce üretilmiş access token'lar reddedilir. JWT `iat` saniye altı hassasiyetle üretilir | Refresh oturumlarını iptal etmek yetmez: 15 dk'lık access token'lar çalışmaya devam ediyordu. Saniye hassasiyetinde aynı saniyede üretilen eski token kabul ediliyordu (test yakaladı) |
| E-posta doğrulama politikası (`VISIONROUTE_REQUIRE_VERIFIED_EMAIL`, varsayılan açık): davet, API anahtarı ve webhook oluşturma doğrulanmış e-posta ister; giriş engellenmez | Ürün akışını bozmadan hassas işlemleri korur; davetle katılan kullanıcılar e-postayı bağlantıyla kanıtlamış sayılır |
| Bilinmeyen hesapla girişte sahte Argon2 doğrulaması yapılır | Önceki erken dönüş, yanıt süresinden hesap varlığını sızdırıyordu (zamanlama oracle'ı) |
| Davet kabulünde plan kullanıcı limiti yeniden kontrol edilir; aynı e-postaya bekleyen davet varken yenisi reddedilir; yeniden gönderim token'ı döndürür | Birden çok bekleyen davet limiti aşabiliyordu |
| Frontend oturum yenileme tek uçuşlu (single-flight); API yanıtları Zod ile doğrulanır; birim testleri Vitest (yeni geliştirme bağımlılığı), MFA QR kodu tarayıcıda `qrcode` ile üretilir | Refresh token yeniden kullanım tespiti eşzamanlı yenilemeleri hırsızlık sayıp oturumu kapatıyordu. QR harici servise gönderilmez (sır tarayıcıdan çıkmaz) |
| Koçluk: `coaching_actions` (RLS) + durum makinesi `open → in_progress → completed`, aktif durumlardan `canceled`; tamamlanan/iptal edilen yeniden açılmaz | Geçmiş değişmez kalır; tekrar gerekirse yeni görev |
| `resolution` serbest metin değil sabit liste (`kocluk_atandi`, `surucu_bilgilendirildi`, `islem_gerekmedi`, `ekipman_kontrolu`, `yanlis_alarm`); `kocluk_atandi` yalnızca `confirmed` kararla ve olay başına tek aktif görev (kısmi benzersiz indeks + yarış durumunda mevcut görevi döndürme) | Tekrarlanan inceleme istekleri çift görev üretmemeli; eşzamanlılık testle doğrulandı |
| Olay inceleyici (koçluk yönetim yetkisi yok) koçluk gerektiğine karar verebilir ama sorumlu atayamaz; sorumlu yalnızca `coaching.manage` yetkili aktif üye olabilir | Rol ayrımı korunur |
| Sürücü (self servis) rolü yalnızca kendi hesabına bağlı sürücünün görevlerini görür | Nesne düzeyinde yetkilendirme; önceki izin kataloğu `coaching.read` veriyordu ama kapsam yoktu |
| `VISIONROUTE_DISABLE_DOTENV=1` | pydantic-settings dict ayarlarını env ve `.env` arasında birleştiriyor; test/CI alt süreçleri geliştiricinin yerel `.env` dosyasından etkilenmemeli |
| Nesne depolama: `boto3` (yeni bağımlılık; geliştirme için `boto3-stubs[s3]`) ile S3 uyumlu adaptör; üretimde AWS S3, yerelde MinIO. Test/geliştirme için HMAC imzalı kısa ömürlü API bağlantıları kullanan yerel dosya adaptörü; üretim benzeri ortamda `storage_backend=s3` zorunlu | Resmî AWS SDK'sı; imzalı POST koşulları (boyut aralığı, sabit Content-Type) ve SigV4 kendimiz yazılmamalı. S3 adaptörü CI'da gerçek MinIO'ya karşı sözleşme testiyle doğrulanır |
| Kanıt medyası akışı: yükleme yuvası (yetki + tür/boyut sınırı + opak anahtar `orgs/<org>/evidence/<id>`) → istemci doğrudan depoya yükler → `complete` nesneyi inceler (boyut eşleşmesi + sihirli baytlar JPEG/PNG/MP4); uyuşmazlıkta nesne silinir ve kayıt `rejected` olur | İstemcinin bildirdiği türe güvenilmez; API sunucusu büyük dosyaları proxy'lemez |
| Ham medya erişimi `events.evidence.raw_media` ister; indirme bağlantısı (varsayılan 300 sn, `attachment`, `no-store`) her üretimde denetim kaydına yazılır, URL kaydedilmez; yükleme/silme ayrıca `events.review` ister. API anahtarları için ayrı `evidence:write` kapsamı; bilinmeyen kapsamlar reddedilir | En az yetki; kamera entegrasyonu telemetri gönderemez ve tersi |
| Otomatik yüz/plaka anonimleştirme **yapılmadı**: medya `redaction_status=not_processed` olarak işaretlenir | Harici bilgisayarlı görü servisi ve eşik/hukuki karar gerektirir; sahte "anonimleştirildi" durumu gösterilmez |
| KVKK talepleri `privacy_requests` tablosunda (FORCE RLS) tutulur ve worker tarafından kira süreli (SKIP LOCKED) işlenir; `background_jobs` kullanılmadı | `background_jobs` kiracı sütunu ve RLS içermiyor; talep kaydı kişinin verisinden bağımsız yaşamalı (konu kimliği yabancı anahtar değil) |
| Dışa aktarma: JSON/CSV içeren ZIP, özel depoda 7 gün, yalnızca imzalı kısa ömürlü bağlantıyla; telemetri 200.000 satır ve medya 100 MB ile sınırlı, kısaltma manifest'te belirtilir. Kullanıcı kendi verisini self servis isteyebilir; hazır olunca e-posta (dosya eke konmaz) | KVKK md. 11 erişim hakkı; e-posta eki kişisel veriyi kontrolsüz kopyalar |
| Silme = sürücü/kullanıcı kimliklerinin takma adla değiştirilmesi + ham telemetri, olay konumları, serbest metin notlar ve kanıt medyasının silinmesi; güvenlik olayı/sefer satırları anonim istatistik olarak kalır; denetim kayıtları korunur | Filo istatistikleri ve yasal yükümlülükler tutarlı kalmalı; salt satır silme toplamları geriye dönük bozardı. Hesap başka organizasyonda kullanılıyorsa yalnızca bu organizasyondaki üyelik ve veriler kaldırılır |
| Kendi hesabının ve organizasyon sahibinin silinmesi talep edilemez; silme için gerekçe zorunlu; yetki mevcut `org.retention.manage` izni | Kilitlenme ve yanlışlıkla sahipsiz organizasyon önlenir; izin kataloğu değişmediği için RBAC seed migration'ı gerekmedi |
| Saklama: organizasyon ham telemetri ve kanıt medyası sürelerini plan sınırı içinde kısaltabilir (en az 30 gün); scheduler saatte bir temizler (telemetri 5.000'lik partiler), süresi dolan dışa aktarma dosyaları, 90 günden eski e-posta kayıtları ve süresi geçmiş tek kullanımlık token'lar silinir | Hukuki süre kararı veri sorumlusunda; ürün yalnızca üst sınırı ve mekanizmayı sağlar |
| Kiracı kapsamlı her tablo FORCE RLS + politika içermelidir; istisnalar (`audit_logs`, `idempotency_keys`, `sessions`) güvenlik testinde gerekçeyle listelenir | Yeni tabloda RLS unutulması regresyon testiyle yakalanır |
